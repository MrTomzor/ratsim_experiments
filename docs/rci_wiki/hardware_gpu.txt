==== Interactive nodes ====

Dedicated node for interactive work dgx10  each with 4 x NVIDIA Tesla A100 with 80GB graphic memory and NVLink3 interconnection. NVLink3 allows very fast communication in multiGPU jobs via libraries like [[https://developer.nvidia.com/nccl|NCCL]]. CUDA compute capability is 8.0. There are available all [[installed_modules_amd|AMD software modules]]. 


===== GPU allocations =====

GPU nodes are in gpu,longjobs and deadline partitions. If you want to work with GPU card, you have to allocate it with SLURM. **GPUs are allocated exclusively, so only 1 user at given time can work with allocated GPU.**

==== Interactive work ====

Interactive work with GPUs is available ony in the partitions: **gpufast,amdgpufast and interactive**.
<code>srun -p gpufast --gres=gpu:2 --pty bash -i</code> will allocate 2 GPUs on a GPU node. Without allocation your job will not see any GPUs:
<code>
user@login1:~$ srun -p gpufast --gres=gpu:1 --pty bash -i

=== Allocating 80GB GPU  ===

There are 32GB memory in the GPUs in the intel nodes and 40GB in the AMD nodes. But there is special node dgx10 with 4 80GB GPUs A100. If this special node is needed, srun should looks like this:

<code>
srun -p interactive --gres=gpu:80gb:1 --pty bash -i
</code>

==== Batch job ====

Multiple nodes with multiple GPUs is possible to allocate for batch job. Prepare your batch file:
<code>
#!/bin/bash
#SBATCH --nodes=2               # number of nodes
#SBATCH --ntasks-per-node=4     # processes per node
#SBATCH --cpus-per-task=2       # number of CPU cores per process
#SBATCH --gres=gpu:4            # GPUs per node 
#SBATCH --partition=gpu         # put the job into the gpu partition/queue
#SBATCH --output=job_%j.out     # file name for stdout/stderr
#SBATCH --mem=100G              # how much CPU memory can be allocated for the job (hardware limit: 384 GB per node)
#SBATCH --time=24:00:00         # maximum wall time allocated for the job (max 24h for the gpu partition)
#SBATCH --job-name=my_test        # job name (default is the name of this file)

ml fosscuda/2019a 
mpirun myjob
</code>
This jobs requires 2 nodes each with 4 GPUs and 8 CPU cores and 100G of the memory. On each node will start 4 processes myjob which requires fosscuda/2019a module. Each process will see 4 GPUs and have to decide which GPU will use.

When more GPUs are requested by sbatch and multiple processes is started by srun (inside sbatch), each process will see all requested GPUs otherwise is restricted by --gres=gpu parameter of srun.  In the following example, 4 GPUs are requested and 4 processes are started inside sbatch, and each process is limited to 1 GPU. 

<code>
#!/bin/bash
#SBATCH --nodes=1               
#SBATCH --ntasks-per-node=4     
#SBATCH --cpus-per-task=1       
#SBATCH --gres=gpu:4           
#SBATCH --partition=gpu         
#SBATCH --output=job_%j.out     

ml fosscuda/2019a
srun --gres=gpu:1 -n1 --exclusive ~/cuda_device_query
srun --gres=gpu:1 -n1 --exclusive ~/cuda_device_query
srun --gres=gpu:1 -n1 --exclusive ~/cuda_device_query
srun --gres=gpu:1 -n1 --exclusive ~/cuda_device_query
</code>

When submited by sbatch command, will generate file job_JOBID.out where output from 4 processes ~/cuda_device_query ( [[https://github.com/NVIDIA/cuda-samples/tree/master/Samples/deviceQuery|CUDA samples deviceQuery utility]]) is stored. Each process will see unique GPU:
<code>

</code>
====== Multi-node multi-GPU tasks ======
 Libraries [[https://developer.nvidia.com/nccl|NCCL]] and [[https://github.com/horovod/horovod|Horovod]] allows run multi-node training jobs. Always use prepared software modules for multinode training. Modules are optimized compiled for RCI cluster environment. [[installed_modules#PyTorch|Available PyTorch modules]] compiled with NCCL support.
===== PyTorch Multi-node NCCL example =====
For example, let's consider the [[https://github.com/pytorch/examples/tree/master/imagenet|PyTorch ImageNet script]]. To run it in the multi-node regime ( 2 GPUs per node, 2 nodes) you can use the following script
<code>
 #!/bin/bash
#SBATCH --job-name=multinode
#SBATCH --output=multinode.out
#SBATCH --time=11:00:00
#SBATCH --partition=gpu
#SBATCH --nodes=2
#SBATCH --ntasks=2
#SBATCH --gres=gpu:2
#SBATCH --mem=128G

module purge
module load PyTorch/1.8.0-fosscuda-2020b

declare -a nodes=()
declare -a ips=()
while read line; do
    nodes+=( $line )
    ips+=( $(getent hosts $line | cut -d' ' -f1) )
done <<< $(scontrol show hostnames $SLURM_JOB_NODELIST)

PORT=$(shuf -i30000-60000 -n1)

srun -N1 -n1 --gres=gpu:2 python main.py -a resnet50 \
                                  --dist-url "tcp://${ips[0]}:$PORT" \
                                  --dist-backend 'nccl' \
                                  --multiprocessing-distributed \
                                  --rank 0 \
                                  --world-size 2 \
                                  /mnt/data/public_datasets/imagenet/imagenet_fullres/train/ &


srun -N1 -n1 --gres=gpu:2 python main.py -a resnet50 \
                                  --dist-url "tcp://${ips[0]}:$PORT" \
                                  --dist-backend 'nccl' \
                                  --multiprocessing-distributed \
                                  --rank 1 \
                                  --world-size 2 \
                                  /mnt/data/public_datasets/imagenet/imagenet_fullres/train/ &

wait 
</code>

===== PyTorch Multi-Node Horovod example =====
In case you would like to use Horovod, you can use the following template with [[https://github.com/horovod/horovod/blob/master/examples/pytorch/pytorch_imagenet_resnet50.py|Horovod ImageNet script]],
<code>
#!/bin/bash
#SBATCH --job-name=multinode
#SBATCH --output=multinode.out
#SBATCH --time=18:00:00
#SBATCH --partition=gpu
#SBATCH --nodes=4 # Number of nodes
#SBATCH --ntasks-per-node=8 # Number of MPI process per node
#SBATCH --gres=gpu:2 # Number of GPUs per node
#SBATCH --mem=128G

module purge
module Horovod/0.22.1-fosscuda-2020b-PyTorch-1.8.0

declare -a nodes=()
while read line; do
    nodes+=( $line )
done <<< $(scontrol show hostnames $SLURM_JOB_NODELIST)

NODES=""
for i in ${!nodes[@]}; do
    if [ "$i" -eq "0" ]; then
        NODES+="${nodes[$i]}:2"
    else
        NODES+=",${nodes[$i]}:2"
    fi
done

horovodrun -np $SLURM_NTASKS --mpi -H $NODES python pytorch_imagenet_resnet50.py --train-dir /mnt/data/public_datasets/imagenet/imagenet_fullres/train/ --val-dir /mnt/data/public_datasets/imagenet/imagenet_fullres/validation/ --batch-size 256

</code>

====== Sharing 1 GPU with multiple tasks ======

When utilization of GPU by one task is low and there are multiple tasks needed to compute, it's possible to create SLURM batch which will run multiple tasks on 1 GPU.
E.g. when 1 task GPU maximum utilization is 25% and requirement of GPU memory is less than 8GB (Tesla V100 has 32GB of graphics memory), it's possible to run 4 tasks on 1 GPU. The utilization of GPU will be better and 4x more tasks can be run at same time.

Example of SLURM batch, where 4 tasks shares 1 GPU:
<code>
#!/bin/bash
#SBATCH --nodes=1               # number of nodes
#SBATCH --ntasks-per-node=4     # tasks per node
#SBATCH --cpus-per-task=1       # number of CPU cores per process
#SBATCH --gres=gpu:1            # GPUs per node
#SBATCH --partition=gpu         # put the job into the gpu partition/queue
#SBATCH --output=mpi_%j.out     # file name for stdout/stderr
#SBATCH --mem=8G              # how much CPU memory can be allocated for the job (hardware limit: 384 GB per node)
#SBATCH --job-name=mpi        # job name (default is the name of this file) 

ml  PyTorch/1.4.0-fosscuda-2019b-Python-3.7.4
export OMPI_MCA_mpi_warn_on_fork=0       #disable MPI warnings
mpirun -np 4  python mpi.py 10     # use mpi to run 4 tasks
</code>

As you can see, MPI is used to run multiple tasks inside 1 job. So OpenMPI module have to be loaded before. All foss-* and fosscuda* modules loads OpenMPI as dependency. When you need to set different argument for each task inside this batch, you have to use MPI environment variable ''OMPI_COMM_WORLD_RANK'' which contains task number. 
Python example script:
<code>
import sys
import os

input = int(sys.argv[1])
task = int(os.environ["OMPI_COMM_WORLD_RANK"])
argument = input+task
print ("Input: " + str(input) + " task: " + str(task) + " argument: " + str(argument) ) 
</code>

Output of the command ''sbatch mpi.batch'' will be:
<code>
nput: 10 task: 0 argument: 10
Input: 10 task: 3 argument: 13
Input: 10 task: 1 argument: 11
Input: 10 task: 2 argument: 12 
</code>

====== GPU Utilization ======

Please, try to get GPU utilization as high as possible. How to get better GPU utilization?
  * Use modules with the latest CUDA version available. CUDA 11.7 can be much faster than CUDA 10.3.
  * With data intensive jobs, always store your data on the fast storage like /mnt/data or /mnt/personal . [[storage|More information about storage]].
  * [[hardware_gpu#sharing_1_gpu_with_multiple_tasks|Try to run multiple jobs on 1 GPU]].
