====== Jupyter notebooks ======

You can use prepared [[interactive|web application]] to run Jupyter notebook on the cluster's compute node in your local browser.

Or with a small amount of configuration, you can create own Jupyter job. The main steps are:

  - Start a jupyter notebook job.
  - Start an ssh tunnel.
  - Use your local browser to connect.

**Use Jupyter notebooks only in fast partitions (cpufast,gpufast ..)!**

===== Start Jupyter server =====
Here is a template for submitting a jupyter-notebook server as a batch job. You may need to edit some of the SLURM options, including the time limit or the partition. You will also need to load required module that contains jupyter-notebook [[installed_modules#notebook|notebook]] or [[installed_modules#ipython|IPhyton]]. Save your edited version of this script on the cluster, and submit it with sbatch.

<code>
user@login1:~$ cat jupyter.batch
#!/bin/bash
#SBATCH --partition cpu
#SBATCH --nodes 1
#SBATCH --ntasks-per-node 1
#SBATCH --mem-per-cpu 8G
#SBATCH --time 1-0:00:00
#SBATCH --job-name jupyter-notebook
#SBATCH --output jupyter-notebook-%J.log

# get tunneling info
XDG_RUNTIME_DIR=""
port=$(shuf -i8000-9999 -n1)
node=$(hostname -s)
user=$(whoami)

# print tunneling instructions jupyter-log
echo -e "
MacOS or linux terminal command to create your ssh tunnel:
ssh -N -L ${port}:${node}:${port} ${user}@login.rci.cvut.cz

Here is the MobaXterm info:

Forwarded port:same as remote port
Remote server: ${node}
Remote port: ${port}
SSH server: login.rci.cvut.cz
SSH login: $user
SSH port: 22

Use a Browser on your local machine to go to:
localhost:${port}  (prefix w/ https:// if using password)
"

ml IPython/7.2.0-foss-2018b-Python-3.6.6
jupyter-notebook --no-browser --port=${port} --ip=${node}
</code>

When finished with editing, you can start jupyter.batch with command:
<code>
user@login2:~$ sbatch jupyter.batch
Submitted batch job 342
</code>

As you can see, notebook has been started on node n01 and in the ''jupyter-notebook-$job_id.log'' are instructions, how to login.

==== Variants ====

Not only IPython module could be loaded. Another variant is to load Anaconda3 module or run singularity container.

<code>
module load TensorFlow/1.13.1-fosscuda-2018b-Python-3.6.6
module load IPython/7.2.0-fosscuda-2018b-Python-3.6.6
jupyter-notebook --no-browser --port=${port} --ip=${node}
</code>
In this example, also TensorFlow module is loaded. Because CUDA variant is selected, partition have to be ''gpu'' and ''gres gpu'' requested so sbatch header should looks like:
<code>
#SBATCH --partition gpu
#SBATCH --nodes 1
#SBATCH --ntasks-per-node 1
#SBATCH --mem-per-cpu 8G
#SBATCH --gres gpu:1
#SBATCH --time 1-0:00:00
#SBATCH --job-name jupyter-notebook
#SBATCH --output jupyter-notebook-%J.log
</code>

Anaconda3 contains also jupyter notebook:
<code>
module load Anaconda3
jupyter-notebook --no-browser --port=${port} --ip=${node}
</code>

Running notebook from container:
<code>
singularity exec --nv /mnt/appl/singularity_images/tensorflow-19.03-py3.simg jupyter-notebook --no-browser --port=${port} --ip=${node}
</code>
Note: this is container required GPU so singularity ''--nv'' switch have to be used also partition with GPU nodes.
===== Start the SSH tunnel =====

Once you have submitted your job and it starts, your notebook server will be ready for you to connect. You can run squeue -u$(whoami) to check. You will see an "R" in the ST or status column for your notebook job if it is running. If you see a "PD" in the status column, you will have to wait for your job to start running to connect. The log file with information about how to connect will be in the directory you submitted the script from, and be named jupyter-notebook-[jobid].log where jobid is the slurm id for your job.
<code>
eb@login2:~$ more jupyter-notebook-342.log

MacOS or linux terminal command to create your ssh tunnel:
ssh -N -L 8660:n01:8660 user@login.rci.cvut.cz

Here is the MobaXterm info:

Forwarded port:same as remote port
Remote server: n01
Remote port: 8660
SSH server: login.rci.cvut.cz
SSH login: user
SSH port: 22

Use a Browser on your local machine to go to:
localhost:8660  (prefix w/ https:// if using password)

[I 21:39:18.620 NotebookApp] Writing notebook server cookie secret to /home/user/.local/share/jupyter/runtime/notebook_cookie_secret
[I 21:39:21.375 NotebookApp] Serving notebooks from local directory: /home/user
[I 21:39:21.375 NotebookApp] The Jupyter Notebook is running at:
[I 21:39:21.375 NotebookApp] http://n01:8660/?token=9613324d1a727ccc100f5702424f42143768f5041bb4ba5b

    Copy/paste this URL into your browser when you connect for the first time,

        http://n01:8660/?token=9613324d1a727ccc100f5702424f42143768f5041bb4ba5b
</code>

==== Linux and Mac OS X ====
On a Mac or Linux machine, you can start the tunnel with an SSH command. You can check the output from the job you started to get the specifc info you need.
<code>
ssh -N -L 8660:n01:8660 user@login.rci.cvut.cz
</code>

==== Windows ====
On a windows machine, we recommend you use MobaXterm. You will need to take a look at your job's log file to get the details you need. Then start MobaXterm:

  * Under Tools choose "MobaSSHTunnel (port forwarding)".
  * Click the "New SSH Tunnel" button.
  * Click the radio button for "Local port forwarding".
  * Use the information in your jupyter notebook log file to fill out the boxes.
  * Click Save.
  * On your new tunnel, click the key symbol under the settings column and choose your ssh private key.
  * Click the play button under the Start/Stop column.

===== Browse the Notebook =====
Finally, open a web browser on your local machine and enter the address http://localhost:port where port is the one specified in your log file. The address Jupyter creates by default (the one with the name of a compute node) will not work outside the cluster's network. Since version 5 of jupyter, the notebook will automatically generate a token that allows you to authenticate when you connect. In the log you can see: 
<code>
http://n01:8660/?token=9613324d1a727ccc100f5702424f42143768f5041bb4ba5b
</code>

so your address will be:
<code>
http://localhost:8660/?token=9613324d1a727ccc100f5702424f42143768f5041bb4ba5b
</code>

===== Stop the Notebook =====

On login node just cancel your SLURM batch job:
<code>
user@login2:~$ scancel 342
</code>
