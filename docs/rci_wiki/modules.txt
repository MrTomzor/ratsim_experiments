====== Software modules ======

On all compute and login nodes it's possible to use so called software modules. ''module'' is software (http://lmod.readthedocs.io/) which can be loaded with all required dependencies and all required environment variables will be set in such way, that software will work. It's possible to have multiple versions of some libraries without conflict.

When loading some module, required environment variables are set. After logout or closing shell, those variables will be unset and all modules will be unloaded automatically. It's possible to  modify starting environment (.bashrc, .cshrc) to load some modules during login.

**There are different modules installed on Intel,AMD and H200 nodes. ** 
Command module uses cache and switching between different types of nodes can confuse output of the module command. Use --ignore-cache to prevent using this cache.
<code>
ml --ignore-cache avail
</code>

==== Loading modules ====
Main command for module manipulation is ''module'' with abbreviation: ''ml'' .

Example:
<code>
eb@n33:~$ python --version
Python 2.7.5
eb@n33:~$ python3 --version
Python 3.4.9
eb@n33:~$ ml Python/2.7.15-foss-2018b
eb@n33:~$ python --version
Python 2.7.15
eb@n33:~$ ml Python/3.6.6-foss-2018b

The following have been reloaded with a version change:
  1) Python/2.7.15-foss-2018b => Python/3.6.6-foss-2018b

eb@n33:~$ python --version
Python 3.6.6
</code>

As you can see system default is python 2.7.5 and python3 3.4.9 After loading module Python-2.7.15, command python will start python 2.7.15. When loading module Python-3.6.6 , command python will start python 3.6.6

Some modules are not from foss* toolchains , but GCCcore toolchains, it means that are not depend on OpenMPI, ScaLAPACK, FFTW or OpenBLAS and can be combined with corresponding foss toolchain. E.g GCCcore-8.3.0 modules can be used with foss-2019b or fosscuda-2019b modules, but not with foss-2019a. Also foss-2019b modules can be combined with fosscuda-2019b modules, because of same GCC used. From foss-2021a, fosscuda toolchain is deprecated. Multiple CUDA versions can be used e.g. foss-2021a-CUDA-11.3.1 or foss-2021a-CUDA-11.4.1.
**There are installed only modules from foss/fosscuda-2020b and up on AMD nodes.**
**There are installed only modules from foss-2023b and up on H200 nodes.**
  
=== Naming convention ===
Modules are named with version + toolchain + other software used. Eg:
**NVCaffe/1.0-fosscuda-2018b-Python-3.6.6**   means NVCafFe version 1.0, compiled with foss 2018b toolchain and with Python 3.6.6 modules. From foss/fosscuda-2020b Python suffix is deprecated, e.g. TensorFlow/2.5.0-fosscuda-2020b . From foss-2021a is fosscuda deprecated and version of CUDA is specified in suffix, e.g. PyTorch/2.7.1-foss-2023b-CUDA-12.4.0 .

==== Python package finder ====

On the login nodes, there is available command line tool **find_python_package** , which searches installed modules for Python packages.

<code>
user@login3:~$ find_python_package -h
find_python_package - searches installed software modules for given Python package or packages

Usage: 
  --package, -p      Python package 
  --list, -l         list of Python packages separated by comma eg. torch,cv2
  --module, -m	      prints all Python packages in given module and its dependencies
  --requirements, -r file with Python requirements
  --verbose, -v      more verbose output
  --help, -h         this help

</code>

==== Anaconda ====
Anaconda2 and Anaconda3 modules are available. So loading module Anaconda3 will set path to Python 3.7 which is part of the [[https://www.anaconda.com/distribution/|Anaconda distribution]] with default [[https://docs.anaconda.com/anaconda/packages/py3.7_linux-64|Anaconda python packages]]. More packages can be installed by conda command. Anaconda module is not compatible with another Python modules like  NVCaffe/1.0-fosscuda-2018b-Python-3.6.6. All required packages have to be installed by conda command.
